Greedy Nose — UI Mocks

Static, framework-agnostic phone mocks for the bank-charge / bad-charge alert app. Layout uses flexbox throughout so it maps fairly directly to React Native, and serves as a precise blueprint if implemented in Flutter or another stack instead.

Flow: connect bank → one-time onboarding review of existing payees → every payee defaults to Bad until marked Good → manage rules (a good payee may carry an optional amount limit) → get notified the next time a bad charge arrives.

These mocks follow ../REQUIREMENTS.md, which is the spec. Comments in the individual files cite the requirement they implement (R5, R12a, …) wherever the reasoning is not obvious from the screen alone.

Screens below are grouped in the order the user meets them, not by file number — the numbers stay on the labels so each frame is easy to find on disk.

1 · Connecting a bank

Started from Settings (R36), for every bank. Search the bank by name, grant access, pick the account if the bank has several, and the bank is saved. The first sync then runs on its own (R25); if the user stays, it ends with one of two choices for the payees that have no rule yet (R26). Leaving earlier changes nothing: the bank stays connected and its payees stay Bad. Only a connect that is cancelled before the account is chosen saves nothing.

2 · Daily use

What the app looks like when the user opens it themselves. The search box is pinned under the title on both list screens, so only the list scrolls (R23). 2d is the one that carries the rule worth getting right — the date grouping survives the filter, so a recurring payee still reads as one charge per month — and 2c is the state a query matching nothing has to reach, since a silently empty list is indistinguishable from a lost connection. 2b has no search box on purpose: with no debits there is nothing to narrow down.

5 · Settings — where banks are managed

Deleting a bank is the only way to end a connection on purpose. It is per bank and confirmed, it wipes only that bank’s debits and it never touches rules (R18). The app opens on the “no bank” state when no bank is connected (R36).

6 · Losing and restoring the connection
